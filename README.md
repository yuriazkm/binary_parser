# Сбор артефактов iOS IPA

## Установка

1. Замените `binary_parser.sh` в корне репозитория.
2. В существующем Codemagic workflow замените только шаг Process ipa на содержимое `codemagic-step.yaml`. Это фрагмент, а не полный workflow. Сборку, подпись и публикацию приложения оставьте как есть.
3. Сохраните `environment.groups: [ipa_processing]`.
4. В строке `${IP_BASE_URL}<upload_type>` замените `<upload_type>` на ваш прежний endpoint. Для присланного Flutter workflow это `upload_fwa`. Скрипт не выбирает бизнес-категорию приложения автоматически.
5. Для Flutter по умолчанию используется `$CM_BUILD_DIR/build/ios/ipa`. Для Native, Unity и других стеков задайте `IPA_SEARCH_DIR` с каталогом экспорта либо `IPA_PATH` с точным путём к IPA. Если найдено несколько IPA, требуется явный `IPA_PATH`.

Ручной запуск на macOS с Xcode Command Line Tools:

```bash
bash binary_parser.sh '/path/My App.ipa' '/path/new-empty-output'
```

Выходной каталог создаётся автоматически и должен быть пустым. Каждый запуск CI использует отдельный временный каталог, который удаляется после окончания шага. Архив имеет прежнее имя и прежние файлы в корне. При ошибке разбора упаковка и отправка не запускаются.

## Что исправлено

В исходной реализации Flutter-путь к файлу `App.framework/App` ошибочно использовался как каталог, получался `App.framework/App/App`. Для Unity была та же ошибка. Сам по себе скриншот не доказывает, что причиной стало изменение Flutter.

Присланный фикс исправляет это, но выбирает произвольный первый файл при неудачном поиске native-бинарника, предполагает совпадение имени `.app` и executable и собирает strings из ресурсов frameworks.

Новая версия читает основной executable из `CFBundleExecutable` (в том числе binary plist), проверяет Mach-O через `file`, не зависит от executable permissions и корректно обрабатывает пробелы. Строки собираются из всех обычных файлов Mach-O внутри приложения, включая frameworks, dylib и расширения. Пустые результаты допустимы, ошибки инструментов завершают процесс с ненулевым статусом. Распаковка производится в отдельный временный каталог без удаления каталогов рядом с исходным IPA.

## Совместимость артефактов

Сохранены семь имён файлов:

- `strings.txt`: уникальные печатные ASCII-строки всех Mach-O приложения. Набор шире и последовательнее, чем раньше; ресурсы frameworks исключены.
- `frameworks.txt`, `external_symbols.txt`, `objc.txt`: прежняя семантика выбора бинарника — основной executable для Native и Flutter, UnityFramework для Unity. Это не объединённые отчёты всех зависимостей. Пути в выводе теперь относительные и не содержат случайный временный каталог.
- `binary_hash.txt`: SHA-256 App.framework/App для Flutter, UnityFramework для Unity, основного executable для остальных. При отсутствии этих framework-файлов используется основной executable. Это хеш одного бинарника, а не всего приложения.
- `info_plist.txt`: `plutil -p` для основного Info.plist.
- `assets_hashes.txt`: уникальные SHA-256 файлов PNG/JPG/JPEG/GIF/WEBP/PDF внутри приложения. Как и ранее, содержимое Assets.car, Unity asset bundles и прочих упакованных ресурсов не извлекается.

Из-за исправленного охвата strings и относительных путей первое сравнение со старыми артефактами может показать различия. Формат запроса на сервер, заголовок, multipart-поле и переменные `IP_DOMAIN`, `IP_IP`, `IP_SECRET_KEY`, `IP_BASE_URL` сохранены. Параметры curl намеренно не менялись: HTTP 4xx/5xx без `--fail` по-прежнему не обязательно дают ненулевой код curl.

## Границы поддержки и проверка

«Все платформы» здесь означает стеки, создающие iOS IPA: Swift/Objective-C, Flutter, Unity, React Native, .NET и аналогичные. Это не парсер Android APK/AAB и не Linux/Windows-утилита. Не требуются Flutter SDK, Unity SDK, Python или сторонние зависимости для запуска парсера.

Проверены локально: Bash-синтаксис, четыре варианта структуры IPA (native/flutter/unity/other), binary plist, несовпадающие имена bundle/executable, пробелы, отсутствие executable bits, отбор Mach-O вместо ресурсов, хеш выбранного бинарника, устранение повторов asset-хешей, отказ при непустом выходном каталоге, отсутствующем/невалидном executable, нескольких top-level .app и повреждённом ZIP. Использованы синтетические IPA с настоящими Mach-O, собранными локальным clang для macOS; это проверка алгоритма, а не реальная iOS-сборка.

Реальных IPA в приложенных материалах нет, поэтому совместимость с конкретными Flutter/Xcode сборками и приём сервером ещё не проверены. Первый прогон выполните на ваших IPA. Скрипт предназначен для IPA, экспортированных вашей доверенной сборкой; это не песочница для недоверенных архивов. Архивы с символическими ссылками отклоняются явно. Обфусцированный, stripped или зашифрованный код нельзя восстановить этим сборщиком; Flutter split-debug-info сюда не входит.
